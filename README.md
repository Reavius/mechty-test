# Бар «Мечты» — барный гид

Единый сайт: `index.html`. Адрес: https://mechty-bar.netlify.app (Netlify; обновление — перетащить zip-архив сайта в Netlify → «Развертывание»).

- **Бар «Мечты»** (левая вкладка) — для гостей, открыта всем, на русском и английском (переключатель RU / EN сверху):
  - **Меню** (главная) — всё меню бара с ценами, как в PDF (цены — числом, без валюты): коктейли, вино, крепкое, пиво,
    без алкоголя, кофе и чай; поиск (на обоих языках) и кнопки разделов. У коктейлей — фото и ссылка «Состав и аллергены».
    Данные и переводы — `js/menu.js`; новая позиция: строка в `MENU` (`n`, `e` — по-английски, `d`/`de` — описание,
    `v` — объём, `p` — цена, `c` — id в карте, если есть). `tools/check.mjs` следит, чтобы у всего был английский.
  - **Состав и аллергены** — коктейльная карта (коктейли, премиксы, шоты, полуфабрикаты): состав — как в меню бара,
    аллергены, срок годности, без крепости. Сюда ведут QR-коды этикеток (`#id`) и ссылка `#card`.
  - Язык: выбор гостя запоминается; без выбора — язык телефона (не русский / казахский — английский);
    ссылка `?lang=en` сразу открывает английский (удобно для QR на столе). «Бартендерам» — только по-русски.
- **Полигон**: репозиторий `Reavius/mechty-test` — здесь пробуются новые функции; готовая версия переносится на Netlify zip-архивом.
- **Бартендерам** (правая вкладка) — технологическая карта, калькулятор замесов, заявка, «Взять на бар», ревизия, этикетки, списания и журнал входов. Для входа нужны фамилия, электронная почта и пароль. В заявке к отмеченной позиции можно вписать количество («5 кг», «2 шт») — оно попадает в копию заявки.
- **Взять на бар** — что взять с собой на бар: тот же список с галочками, что у заявки, по разделам (настойки, премиксы, крепкое, вина, заготовки, напитки, расходники…). Отмеченное собирается сверху, к позиции можно вписать количество числом; «Скопировать список» — по разделам. Отметки — на этом устройстве.

`calc.html` оставлен только как переадресация на `index.html#bartenders`.

Сайт ставится на телефон как приложение («На экран Домой» / «Добавить на главный экран») и открывается без интернета: `manifest.webmanifest`, `sw.js`, иконки — в `icons/`.
Как в приложении: свайп влево/вправо переключает «Бар «Мечты»» и «Бартендерам», «+» в ревизии и галочки в заявке отзываются короткой вибрацией (на Android; iPhone вибрацию сайтам не даёт), пока грузятся журнал и ревизия — видны заглушки-скелеты.

Превью ссылки в Telegram, WhatsApp и ВКонтакте — картинка `og.jpg` (1200×630) и теги `og:*` в `index.html`. Telegram запоминает превью: после замены картинки обновить его можно через бота @WebpageBot.

## Автопроверки

При каждом изменении GitHub Actions («Проверка сайта», `.github/workflows/check.yml`) прогоняет:

- `tools/check.mjs` — код разбирается, все файлы и фото на месте, офлайн-кэш полный, данные карты целы, id позиций (и значит QR-коды) уникальны, в открытой карте нет граммовок, в репозитории нет паролей и расшифрованных файлов;
- `tools/smoke.mjs` — сайт в настоящем браузере: карта, поиск, ссылки `#позиция`, окно входа, неверный пароль, без ошибок в консоли.

Если в Settings → Secrets and variables → Actions добавить секрет `MECHTY_PASSWORD` (пароль бартендеров), проверки ещё и расшифруют данные и пройдут по всем разделам «Бартендерам». Журнал и ревизия в проверках подменяются — в таблицы ничего не пишется. Без секрета всё остальное тоже проверяется.

Запустить у себя (Node.js 18+): `node tools/check.mjs`; браузерный — `npm i --no-save playwright-core`, `python3 -m http.server 8765`, `CHROME=/путь/к/chrome node tools/smoke.mjs`.

## Бэкап

- **Сайт и данные** — 1-го числа каждого месяца GitHub Actions («Бэкап», `.github/workflows/backup.yml`) создаёт выпуск `backup-ГГГГ-ММ` в разделе Releases: архив сайта, `data.js` (рецептуры — зашифрованы) и `Code.gs`. Запустить вручную: Actions → «Бэкап» → Run workflow. GitHub выключает расписание, если в репозитории 60 дней не было изменений, — тогда включите его там же.
- **Таблицы Google** (журнал входов, ревизия, журналы списаний и проработок) — копирует Apps Script. Один раз: в редакторе Apps Script выберите функцию `installBackup` → «Выполнить» → разрешите доступ к Диску. Копии с датой появляются в папке «Бар Мечты — бэкапы» на Google Диске 1-го числа, хранятся последние 12.

## Анимации

Анимации GSAP включены для всех: заставка с векторной молнией при открытии сайта/приложения (раз за вкладку),
появление заголовка и карточек, «парящие» фото, плавный переход между вкладками, мелкие эффекты в «Бартендерам».
`?fx=0` — выключить на этом устройстве, `?fx=1` — включить обратно; при «Уменьшении движения» анимаций нет.
Код — `fx.js`, библиотека — `vendor/gsap.min.js`, `vendor/ScrollTrigger.min.js` (GSAP Standard License, бесплатно).

## Как устроена защита

- Рецептуры лежат в `js/data.js` в зашифрованном виде: ключ получается из пароля через PBKDF2-SHA256 (600 000 итераций), шифр AES-256-GCM. Без пароля их не прочитать.
- Пароль нигде не сохраняется. После входа на устройстве остаётся ключ расшифровки в IndexedDB — без срока, до нажатия «Выйти» или смены пароля. Пароль вводить заново не нужно.
  Safari на iPhone не всегда сохраняет неизвлекаемый ключ (или отдаёт его непригодным) — поэтому рядом лежит копия ключа; без
  IndexedDB — в localStorage. «Выйти» стирает всё.
- **Участники** («Бартендерам», под журналом входов, кнопка «Показать») — все, кто когда-либо входил: по одному на почту
  (фамилия — из последнего входа), по алфавиту. Почта целиком на сайт не уходит: Apps Script отдаёт первые 3 символа,
  8 звёздочек и окончание адреса (`yak********.com`).
- **Чеклист открытия** («Бартендерам» → «Чеклист», перед «Взять на бар») — общий для всех барменов: отметили пункт —
  он зачёркнут, видно, кто и когда; отметки в Apps Script (свойство `CK`), сверка раз в 30 секунд, без связи ждут на телефоне.
  «День бара» начинается в 06:00 по Астане — тогда список пуст. Разделы А–Д — дела по зонам (список — в `js/open.js`),
  пункты по дням (ревизия — чт, вс; маркировки — пт) видны всегда, в свой день пометка выделена. «Е. Финальная проверка» —
  что ещё не отмечено и «Бар готов к открытию».
- **Новое в заметке к списанию** — красная цифра на кнопке «Списания» (и на значке приложения, где телефон это умеет):
  строки, записанные не вами и ещё не виденные на этом телефоне. Сверка раз в 2 минуты, пока сайт открыт, и при
  возвращении на сайт; открыли заметку списаний — цифра пропадает. Когда сайт закрыт, уведомлений нет.
- **Заявки** — в каждой (заготовщиков и общей) можно добавить позицию, которой нет в списке: «Нет в списке?» — название и
  количество («Изюм», «100 гр»). Она встаёт в раздел «Своё», копируется вместе с заявкой; снятая галочка или × убирает её совсем.
- Каждое открытие раздела «Бартендерам» записывается в журнал: дата, фамилия, почта.
- В журнал могут писать и читать его только те, кто знает пароль: токен журнала хранится внутри шифровки, а Apps Script сверяет его SHA-256. На сайт возвращаются только фамилии и время, почты видны только в таблице.
- После неверного пароля следующая попытка возможна через 2, 4, 8… (до 60) секунд.

## Скорость

- Apps Script в каждом запросе открывает таблицу, лист и папку один раз; старые листы списаний переносит один раз (флаг
  `WO_MIGRATED_<вид>`), id папок помнит в свойствах (`WO_DIR_<вид>`), акт ищет по id поиском, а не чтением всего журнала.
- Общая блокировка: занята дольше 10–20 с — ответ «busy», сайт повторит сам. Сверки (ревизия, месячная, заметка) — без блокировки.
- Заметка: перенос, возврат и отметки пишутся одним вызовом на столбец (RangeList), а не по ячейке.
- Ошибки сохранения акта пишутся в «Выполнения» Apps Script (`console.error`).
- Сайт: страница ждёт сеть не дольше 4 секунд, дальше открывается сохранённая копия (её код — тоже из копии); заставку можно
  пропустить касанием; поиск в месячной ревизии — после паузы в наборе.

## Ревизия

Раздел «Бартендерам» → «Ревизия». Числа складывает Apps Script, вбивать «+» не нужно.

- **День ревизии — с 9:00 до 9:00** по времени Астаны (UTC+5) и часам сервера Google, а не телефона. Ревизия дня одна на всех,
  считать её можно параллельно: например, Куклин — Кафе, Журавлев — Клуб, Кувайцев — Склад. В 9:00 день закрывается сам;
  числа, не успевшие уйти до 9:00, не записываются (сайт предупреждает).
- **«Войти в ревизию»** — видно, кто какую зону считает и что уже посчитано. Вход ничего не создаёт в таблице.
- Зоны: Кафе, Склад и проход, Клуб, VIP, Мансарда, Синий контейнер. Столбец зоны на листе **«По зонам»** появляется с первым
  числом в этой зоне и закрепляется за тем, кто начал (строки 1–3: дата, фамилия, зона); зоны, где ничего не считали, столбцов не получают.
  На кнопке зоны — фамилия того, кто её считает, или «свободна».
- В чужую зону добавлять можно: число прибавится к её столбцу, в журнал запишется под фамилией того, кто добавил. Чужие числа
  на сайте не правятся — отменить (↶) можно только своё.
- **«Завершить»** — личное: ревизия сворачивается у этого бармена и показывает итог дня по всем зонам; остальные продолжают.
  До 9:00 можно «Вернуться в ревизию». Кто завершил — видно остальным.
- Лист **«Итог»**: в столбце A позиции с 3-й строки; у каждого дня — один столбец (строка 1 — дата, 2 — все, кто считал),
  сумма всех зон дня. Появляется с первым числом дня.
- Лист **«Ревизия журнал»** — каждое добавление отдельной строкой (кто, когда, зона и чья она, позиция, сколько).
- Пока раздел открыт, сайт раз в 30 секунд сверяется с таблицей (числа других, кто начал какую зону); пока вводится число — не обновляет.
- ID таблицы ревизии (из адреса `…/spreadsheets/d/<ID>/edit`) — в `REV_BOOK_ID` в Apps Script (уже вписан). Другая таблица — поменяйте его там.
- Позиции в штуках — список `PCS` в Apps Script (Корона, Ред Булл / Рэд Булл, Байкал), остальные считаются в литрах.
- Таблица занята (другой бармен пишет, идёт месячная ревизия) — Apps Script отвечает «busy», и сайт повторяет добавление сам:
  число остаётся «не отправлено», пока не запишется, ничего не теряется. Пока ответ идёт, можно вводить следующее число —
  поле и клавиатура остаются на месте.


### Месячная ревизия

«Ревизия» → «Месячная»: весь бар по бланку — лист **«Месячная ревизия»** в той же таблице ревизии. Лист создаётся сам при первом открытии, точь-в-точь как бланк бара
(столбец A — код или «к», B — наименование, C — ед. изм., разделы — объединёнными строками). Список правится прямо в листе:
строка с названием в B — позиция, строка с текстом только в A — раздел.

Одна месячная ревизия идёт несколько дней и считается несколькими людьми одновременно:

- **«Войти в ревизию»** → вопрос **«Какая зона подсчёта?»**: те же зоны, что в ежедневной, можно выбрать несколько.
  Столбец бармена называется по фамилии и зонам — «Куклин · Клуб и VIP». Первый вошедший заодно начинает ревизию: в листе
  появляется столбец **«Итог»** (первый столбец ревизии: сумма столбцов барменов справа; его можно поправлять руками).
- Одну зону одновременно считает один бармен: занятая зона в выборе недоступна («считает Журавлев»), сервер тоже не даст её взять.
- **«Сменить зоны»** — другой набор зон, другой столбец; прежний закрывается, зоны освобождаются. Выбрать снова те же зоны —
  тот же столбец откроется опять (числа на месте). **«Завершить мой подсчёт»** — столбец закрыт, его зоны свободны.
- На сайте у каждой позиции — итог, своё и чужие числа, прошлая ревизия; поиск по названию и разделу («виски» найдёт все виски), фильтр «Не посчитано», ввод с умножением «0,7×6», отмена, работа без связи.
- **Нет в списке?** — наименование, количество, ед. изм. → позиция встаёт вниз листа, в раздел «Новые позиции», количество — в свой столбец. То же название (без учёта регистра) прибавляется к уже добавленной строке.
- **«Закрыть ревизию для всех»** — все столбцы завершены, «Итог» фиксируется (ручные правки сохраняются). Следующая — снова «Войти в ревизию».

Шапка столбцов: строка 3 — название ревизии, 4 — служебный id (по нему сайт находит столбцы, даже если в лист вставили новые), 5 — «фамилия · зоны» или «Итог», 6 — дата.
Сверка раз в 30 секунд идёт без блокировки таблицы (если в листе нечего чинить) — она не задерживает добавления других.
Формулы «Итога» при начале и закрытии пишутся пачками, а не по ячейке.
Нужен новый `Code.gs` и новая версия развёртывания.
## Списания

Раздел «Бартендерам» → «Списания», два вида актов (переключатель вверху, как у заявки):
- **Акт списания** — акт о списании по бланку ООО «Заря», подразделение «Бар»; причина — у каждой позиции своя;
- **Акт проработки** — тот же бланк и та же логика, в заголовке — «АКТ проработки», причина у всех позиций уже вписана: «Проработка».

Дата, № (необязательно), позиции (наименование — с подсказками из бланка ревизии, ед. изм. л/мл/гр/кг/шт, количество, причина) —
не больше 25 в одном акте, фамилия — из входа, инициалы, подпись пальцем. «Создать файл» — PDF A4 по бланку на **один лист**
(шапка, «УТВЕРЖДАЮ», таблица, сумма, ответственность, подписи; подпись бармена и Фамилия И.О. — в строке «Материально
ответственное лицо»). В таблицу попадают только заполненные строки; длинные наименования и причины переносятся внутри ячейки.
Файл создаётся на телефоне, и сразу же, по той же кнопке, акт уходит в Apps Script двумя запросами: маленький — строки акта
в журнал (акт сразу в истории сайта; браузер доставит его, даже если телефон тут же свернут), и следом PDF — на Google Диск
(ссылка дописывается в строки акта). «Скачать» и «Поделиться» появляются, когда таблица подтвердила сохранение («Акт сохранён —
он в истории и на Google Диске»), поэтому в чат не уйдёт акт, которого нет в истории. Не сохранилось (нет связи, таблица не
ответила) — акт ждёт на телефоне и отправляется сам: через 5 с, 15 с, 30 с, дальше раз в минуту, пока сайт открыт; при появлении
связи, при возвращении на сайт и при входе — на любой вкладке. Можно нажать «Отправить ещё раз»; «Скачать без копии» появляется,
если отправка не удалась или идёт дольше 20 секунд. В PDF страница — 16 оттенков серого со сжатием без потерь (≈80 КБ вместо
≈370 КБ JPEG, чётче); телефон без сжатия (iPhone до iOS 16.4) делает JPEG. У каждого вида и у каждого бармена свой черновик;
после выхода из аккаунта подпись и созданный акт с формы убираются.

**Вставить списком** — под позициями акта: вставьте текст (по позиции в строке: «Водка Беленькая — 170 мл», «Трипл сек 30 + 30 мл»,
«40 мл окхарт», «Ягоды 330 гр — Порча», «Сок 1 л + 200 мл» → 1200 мл, «Клавис 20 мл х2» → 40 мл, «Ред Булл 250мл 2» → 2, размер —
в названии) или строки из таблицы (столбцы через Tab). Сайт сам заполнит наименование, количество, единицу и причину. Перед добавлением
видно, как понята каждая строка; где единицы нет — «ед.?», выберите в форме (единица из ревизии не подставляется — она бывает другой).
Заголовки («Алко», «Итого») пропускаются. У проработки причина — «Проработка», у списания — из строки или общая «для строк без
причины». Не вошедшее в 25 позиций и не понятые строки остаются в поле (и после перезагрузки) — для следующего акта.

**Заметки** — у каждого вида акта своя: «Заметка к списанию» (лист «Заметка» в «Журнале списаний») и «Заметка к проработке»
(лист «Заметка» в «Журнале проработок»; причина всегда «Проработка», поля причины нет). Окно показывает заметку выбранного вида
акта; строки заметки списаний не попадают в акт проработки и наоборот. При переносе одинаковые позиции складываются в одну строку
акта: то же наименование (регистр, «ё» и порядок слов не важны — «Лайм свежий» = «Свежий лайм») и та же причина, единицы
переводятся (гр↔кг, мл↔л): 200 гр + 0,1 кг = 300 гр. Другая причина или несовместимые единицы (шт и л) — отдельные строки.
↩ у сложенной строки возвращает в заметку все её строки. Ниже — подробно о заметке списаний (у проработки всё так же).
Строки проработки, записанные до разделения в общую заметку (она стала заметкой списаний), переносятся один раз:
в Apps Script выберите `noteToProrabotka` → «Выполнить» — открытые строки заметки списаний уйдут в заметку проработки.

**Заметка к списанию** — окно в жёлтой рамке сверху раздела, общее для всех барменов: что списать (наименование, кол-во, ед., причина),
например чтобы завтрашний бармен оформил акт. Удалить строку нельзя. «Перенести в акт списания» закрепляет строки за барменом
и его телефоном на 24 часа: в заметке их больше не видно, в акте их нельзя изменить — только вернуть в заметку (↩).
Акт создан на телефоне — строки сразу помечаются в таблице «в акте …, ждёт копии» и больше не возвращаются, даже если копия
акта дойдёт до Диска позже; копия дошла — «Акт … · кто · id», списаны окончательно. Не создал акт за 24 часа — строки сами
возвращаются в заметку (и уходят из акта) и ждут следующего акта. Если при переносе пропала связь, закреплённые строки придут при
следующей сверке — на этом же телефоне появится кнопка «Вставить в акт» (сама по себе сверка форму акта не трогает).
Если одну строку всё же списали двумя актами (оба телефона были без связи), в листе «Заметка» будет «⚠ также в акте …».
Без связи записанное ждёт на устройстве. История — лист «Заметка» в «Журнале списаний»: кто записал, кто и когда взял в акт,
каким актом списано, с какого телефона. Отметки прежних версий сайта в «Списано в акте» считаются закрытыми, как и были.

**Последние акты** — 30 последних, каждый раскрывается: позиции и ссылка на PDF. Акт, чей PDF удалён с Диска (или удалён весь журнал),
на сайте не показывается; его строки в журнале остаются — их можно стереть там же. Акт, чьи строки уже в журнале, а PDF ещё на
телефоне бармена, помечен «PDF ещё не на Диске». Список сразу показывается из копии на телефоне и обновляется из таблицы.
Проверка «PDF не удалён» — не больше 10 файлов на Диске за одно открытие, ответ помнится 30 минут: удалённый PDF может
показываться в истории до получаса.

Копия — в Apps Script. У каждого вида своя папка на Google Диске — **«Бар Мечты — Списания»** и **«Бар Мечты — Проработки»**:
в ней PDF актов и таблица-журнал (**«Журнал списаний»** / **«Журнал проработок»**), где каждая позиция — строкой (дата, №,
наименование, ед., кол-во, причина, кто, ссылка на файл). Таблица ревизии не меняется. Без связи акт ждёт на устройстве (IndexedDB)
и отправится позже; повтор не дублируется (у акта свой id). Сайт отправляет акт одним POST и читает ответ; если ответ не прочитать,
спрашивает таблицу (`wo=check`), записан ли акт.
Один раз после обновления Apps Script: выберите `checkWriteoff` → «Выполнить» → разрешите доступ к Диску (создадутся обе папки
и оба журнала). Если в таблице ревизии остались листы «Списания» / «Проработки» от прошлой версии, их строки переносятся в журналы,
а сами листы удаляются.
Файлы лежат на Диске владельца Apps Script: ссылки «открыть» / «файл» открываются у него и у тех, с кем он поделится папками
(лучше — с конкретными аккаунтами, не «по ссылке»: в файлах подписи).

## Бар-менеджер

«Бартендерам» → «Менеджер» — раздел управляющего, вход по **отдельному паролю менеджера** (пароль бармена его не открывает).

**Задать или сменить пароль менеджера:** Apps Script → «Настройки проекта» (шестерёнка слева) → «Свойства скрипта» →
«Добавить свойство»: `MGR_PASSWORD` = пароль → «Сохранить». При первом входе пароль заменяется своим хэшем
(`MGR_HASH`, `MGR_SALT`), открытый из свойств удаляется. Сменили пароль — все телефоны менеджера входят заново.

- Пароль уходит в таблицу запросом POST (в адресе его нет); в ответ телефон получает ключ на 30 дней, в свойствах
  скрипта хранится только хэш ключа (`MGR_KEYS`). Ключ привязан к бармену, который вошёл: «Выйти» из «Бартендерам»
  стирает и его. 5 неверных паролей за 15 минут — вход закрыт на 15 минут.
- **Списания и проработки** за любые даты («с» — «по», или «7 дней», «Этот месяц», «Прошлый месяц», «30 дней»):
  итог, по причинам, позиции (одна позиция в мл и л складывается), по барменам, список актов со ссылками на файлы.
  Фильтр «Всё / Списания / Проработки». «Скопировать сводку» — текстом, чтобы переслать.
  Источник — «Журнал списаний» и «Журнал проработок»: удалили акт — сотрите и его строки в журнале.
- **Гостям** — меню и «Состав и аллергены» из таблицы, чтобы менять их без разработчика (смена карты, цены, новые позиции).
  Один раз: «Перенести меню и состав в таблицу» — в таблице ревизии появляются листы **«Меню»** (строка — позиция:
  глава, раздел, название и описание RU/EN, объём, ед., цена, id в карте, код R-Keeper, «скрыть»), **«Карта»** (позиции
  «Состава и аллергенов» и этикеток: id, название и состав RU/EN, полный состав для этикетки через «;», аллергены, объём
  подачи, фото, значок, «только этикетка», «скрыть») и **«Карта разделы»**. Подсказки — в заметках к заголовкам столбцов.
  Дальше правка — на сайте («Меню» / «Состав»: нажать на позицию, «+ Добавить», «Скрыть», «Удалить»; новый раздел меню —
  вписать его название в «Где в меню») или прямо в таблице (порядок строк = порядок в меню). Гости получают данные
  без пароля (`pub=1`), сайт хранит копию на телефоне и открывается сразу и без интернета; правка с сайта видна гостям
  сразу, правка в таблице — в течение 5 минут. Пустое «EN» — гость видит русское; пустое название или описание у позиции
  меню со ссылкой на состав — берутся из «Карты». id позиции «Карты» не менять — на него ведут QR-коды этикеток.
  **Цены R-Keeper** — загрузить прейскурант (Excel / CSV): сайт сопоставит блюда с меню (по коду R-Keeper или названию,
  похожее — «проверьте»), покажет, какие цены изменятся, и применит отмеченные; коды R-Keeper запоминаются в листе
  «Меню». Позиции с двумя ценами («350/890») — вручную. Пока листов нет, меню и состав — из файлов сайта (`js/menu.js`,
  `js/data.js`), как раньше.
- **Отчёт** — каждый понедельник в 9:00 по Астане письмо за прошлую неделю: странности последней ежедневной ревизии
  (как во вкладке «Расход», ±50%), списания и проработки (по причинам, чаще всего, по барменам), приход по поставщикам,
  что сейчас ниже нормы, ревизии недели, открытия смен и входы в «Бартендерам». Во вкладке — предпросмотр (прошлая /
  эта неделя), адреса получателей (через запятую; пусто — владельцу таблицы), «Включить / Выключить по понедельникам»
  и «Отправить сейчас». Открытия смен пишет чеклист: отметка «Бар готов к открытию» → лист **«Открытия смен»** в таблице
  журнала (день, время, кто, сколько пунктов не отмечено). Если сайт пишет «нет разрешения»: Apps Script → выбрать
  `installWeeklyReport` → «Выполнить» → разрешить доступ к почте; таймер включится сам.
- **Справочник позиций** — лист «Справочник» в таблице ревизии, одна строка на позицию бланка месячной ревизии
  (раздел, позиция, ед. изм., код R-Keeper, тара, норма, поставщик, цена закупки, заметка). Лист создаётся сам при
  первом открытии, новые позиции бланка дописываются сами; код R-Keeper берётся из столбца A бланка, если там число.
  Заполнять можно в таблице или на сайте («Менеджер» → «Справочник»: поиск, фильтры «Без нормы / тары / кода»,
  нажать на позицию — правка). **Тара** — объём или вес одной бутылки / упаковки в единицах позиции (0,7 — бутылка
  0,7 л), **норма** — сколько держать, в тех же единицах. Это основа для автозаявки, прихода и сверки с R-Keeper.
- **Продажи** — продажи R-Keeper против ревизии. Выбрать две ревизии (месячные — для всех позиций; ежедневные — только
  для своего списка), выгрузить из R-Keeper «продажи по блюдам» за период между ними (Excel / CSV) и загрузить на сайте.
  Столбцы (блюдо, код, количество, сумма) находятся сами; строки разделов и «Итого» пропускаются. Расход на одно блюдо —
  лист **«Расход на блюдо»** в таблице ревизии (блюдо × позиция справочника × количество в единицах позиции; «—» —
  не учитывать). Сайт предлагает его сам: по техкарте блюда (ингредиенты → позиции справочника, мл → литры / бутылки
  по таре; редкие слова весят больше: «Сарти Роза» — это «Сарти», а не чай «Роза») или по названию напитка (латиница
  тоже: «Hendrick's» → «Джин Хендрикс», объём из названия или меню). «Верно» / «Подтвердить все предложенные» /
  «Изменить» / «Не учитывать» — один раз, дальше запоминается. Итог по позициям: по продажам, по ревизии (было + приход
  − стало − списания), разница («−» — недостача, «+» — излишек) и в тенге по цене закупки из справочника; блюда без
  заданного расхода в итог не попадают. Ингредиент без единицы или тары в справочнике в подсказку не попадает (сайт
  пишет «без: …»). Премиксы, заготовленные про запас, дают «недостачу» спирта — учитывайте остаток премиксов.
  В листе «Расход на блюдо» — граммовки порций: не открывайте к нему общий доступ.
- **Автозаявка** — к заказу = норма − последний остаток, по позициям справочника с нормой; с тарой — целыми
  бутылками / упаковками («3 бут. по 0,7 л», «2 уп. по 24 шт»), без тары — в единицах позиции. Остаток — из самой свежей
  ревизии: ежедневной (последний законченный пересчёт листа «Итог»; позиции сопоставляются по названию — какие не нашлись
  в справочнике, сайт перечисляет) или месячной (последняя закрытая; пока идёт новая — прошлая). Группы по поставщикам,
  галочкой можно убрать позицию; «Скопировать» — по поставщику или всю заявку. Позиции с нормой, которых не было
  в ревизиях, — отдельным списком «Нет остатка». Приход из «Журнала прихода» после даты ревизии прибавляется к остатку.
- **Расход и странности** — по каждой позиции между соседними ревизиями: расход = было + приход − стало; списания
  и проработки (по названию позиции, в её единицах) — сколько из расхода объяснено актами. Последний период сравнивается
  с обычным расходом позиции — медиана «в день» за до 8 прошлых периодов (у ежедневной ревизии — по тем же дням недели,
  если таких периодов 3 и больше). Странности: остаток вырос без прихода; расход выше обычного; расход ниже обычного
  (часто — ошибка пересчёта). Чувствительность ±30% / ±50% / ±100%; мелочь меньше 0,1 л (кг) или 1 шт не считается.
  Ежедневная ревизия — последние 60 пересчётов листа «Итог» (позиции сопоставляются со справочником по названию;
  какие не нашлись — перечисляются, приход и списания для них не учитываются), месячная — последние 24 закрытых «Итога».
  Нажать на позицию — её расход по периодам.
- **Приход** — накладные R-Keeper: выгрузить в Excel (.xlsx) или CSV и загрузить в «Менеджер» → «Приход».
  Файл читается прямо в браузере (`js/xlsx.js`, без сторонних библиотек; старый двоичный .xls — сохранить как .xlsx).
  Сайт сам находит шапку и столбцы (дата, №, поставщик, код, наименование, ед., количество, цена, сумма) — их можно
  поправить; дату, № и поставщика, если их нет в столбцах, берёт из строк над таблицей («Накладная № 125 от 11.10.2026»,
  «Поставщик: …»). Строки сопоставляются со справочником: по коду R-Keeper, по названию, которое уже встречалось,
  иначе — похожее название («проверьте»); незнакомое можно выбрать вручную или пропустить. Коэффициент — сколько единиц
  позиции в одной единице R-Keeper (бутылка при таре 0,7 → 0,7 л). Запись — в лист **«Журнал прихода»** таблицы ревизии
  (количество уже в единицах позиции); повторная загрузка той же накладной не задваивает строки. Справочник запоминает
  название и коэффициент R-Keeper (столбцы J, K), код — если был пуст, и цену закупки за единицу позиции.
  Ниже — накладные за 30 дней / этот / прошлый месяц.

## Этикетки

Раздел «Бартендерам» → «Этикетки»: на позицию две этикетки — лицевая (название, значок, веточки) и оборотная
(сверху название со значком, по углам узоры; слева — состав столбиком, изготовлено — сегодня, годен до — по сроку, кто сделал; справа — QR-код на позицию в открытой карте).
Текст оборотной — самым крупным шрифтом, какой влезает в своё поле: длинные строки переносятся по словам, а не мельчают.
Узоры и значки — векторные (`js/lart.js`), QR — клетками ровно по точкам принтера (3 точки при 203 dpi), поэтому печать чёткая. Дата и фамилия подставляются заново при каждом сохранении. Размер 50×30 мм (принтер бара). У позиции может быть короткое имя для этикетки — поле `ln` в `pub`. Значки: свои (лимон, ягоды) и набор `labels/i-*.png`.
«Поделиться / сохранить» отдаёт PNG — его можно открыть в приложении Niimbot. Украшения — `labels/*.png`, QR — `vendor/qrcode.js` (MIT).
Нижний левый уголок оборотной стоит на 0,6 мм ближе к тексту (к смайлу), чем край рисунка: принтер сдвигает печать вправо, рисунок
прижат влево. Позиции только для этикеток (в открытой карте их нет) — поле `lo: true` в `pub` (сироп сахарный, пена игристого):
без QR-кода. В открытой карте нет температуры хранения — только срок годности.

## Один источник данных

Все данные — в одном `vault.json` (выгружается командой `decrypt` ниже):
`r` — рецептуры калькулятора, `k` — технологические карты, `z`/`zo` — заявки, `zn` — список «Взять на бар», `pub` — открытая коктейльная карта.

- Состав позиции открытой карты с полем `rid` берётся из рецептуры, замес в техкарте с полем `c` (заготовки, настойки) — тоже из рецептуры. Правится в одном месте — в `r`.
- `pub` записывается в `js/data.js` открытым текстом, остальное — в шифровку.
- Названия ингредиентов единые: «Джин сухой «Барристер Драй»», «Сироп ванильный», «Пена пломбир п/ф» и т. д.
- Состав для гостей (`m` в `pub`) — строкой, точь-в-точь как в меню бара: `tools/menu.json` по id позиции. У новой позиции его нужно вписать туда, иначе `vault.mjs` откажется шифровать. Этикетки и техкарты — с полными названиями (`c`).

## Заметки на потом

### Бар-менеджер

Сводка, расход и странности, продажи против ревизии, автозаявка, приход, справочник, «Гостям» и еженедельный

  «Взять на бар» и пункты чеклиста, фото коктейлей (загрузка с телефона) — чтобы менять без разработчика.

### Гость

- Стоп-лист: бармен отмечает «закончилось», в меню и в «Составе и аллергенах» позиция помечается «нет в наличии»
  (через ту же таблицу Google, что и журнал).

## Смена пароля или рецептур

Нужен Node.js 18+.

```sh
# выгрузить все данные (файл НЕ коммитить)
MECHTY_PASSWORD='текущий-пароль' node tools/vault.mjs decrypt > ~/vault.json
# зашифровать заново — тем же или новым паролем
MECHTY_PASSWORD='новый-пароль' node tools/vault.mjs encrypt ~/vault.json
```

Если пароль сменился, скрипт создаст новый токен и напечатает `TOKEN_SHA256`. Вставьте его в Apps Script и выпустите новую версию.
